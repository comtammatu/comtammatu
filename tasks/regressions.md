# Regressions — Named Failure Rules

> Loaded at the start of every session. Each line prevents a past mistake from recurring.
> Format: [DATE] [RULE NAME] — short description

- [2026-04-23] INVENTORY-BRANCH-FILTER-URL-ONLY — Inventory scope ALWAYS flows through URL `?branchId=` (see `apps/web/app/inventory/_lib/inventory-scope.ts#resolveInventoryBranchScope`). Never persist selection to localStorage, cookies, or React context. Server Actions that mutate branch-scoped data MUST take an explicit `branchId` input and re-validate it against the resolver's `allowedBranches` — never trust URL params as a write target. Multi-item RPCs (GRN confirm, transfer commit, stocktake post, production yield) MUST receive a concrete `branchId`; never pass "all" or null. Reports and dashboard aggregation are the ONLY pages allowed to ignore the param.
- [2026-04-23] PO-STATUS-DERIVATION-IN-RPC — Purchase-order status derivation (`sent` → `partially_received` / `received`) triggered by GRN confirmation MUST live inside `confirm_goods_receipt_note` RPC, locked via `SELECT … FROM purchase_orders … FOR UPDATE`. Never re-introduce app-layer computation (pre-fetch `po_id` + read siblings + `UPDATE purchase_orders`): two concurrent confirms against the same PO race and can clobber each other's status. Tolerance is ±5% per ingredient (lower bound only) per `docs/ref/inventory.md §7`. The RPC now returns `{grn_id, status, journal_entry_id, po_id, po_status}` — callers read `po_id` from the response for revalidatePath.
- [2026-04-22] DESIGN-SYSTEM-CONTRACT-FIRST — Before any UI/UX rebuild, read `docs/spec/design-system.md` and `docs/modules/ui.md`, then state the surface, primary user job, route family, change type, and shadcn primitives used. Never start from a new theme, fake primitive, route-specific visual system, or vocabulary source.
- [2026-04-23] PLPGSQL-RECORD-IS-NOT-NULL — `IF record IS NOT NULL` in PL/pgSQL returns TRUE **only when every column is non-null**, not when a row was found. Tenant-level users with `branch_id IS NULL` silently fell out of the JWT hook because one nullable column tripped the check. Check a guaranteed-non-null column (`record.tenant_id IS NOT NULL`) or use `FOUND` after the SELECT. Caught by: area_manager / office / super_manager login returning empty `app_metadata` on 2026-04-23.
- [2026-04-22] JWT-CLAIMS-NOT-IN-APP-METADATA — `session.user.app_metadata` (supabase-js) reads from the `auth.users` row, NOT from JWT claims. Hook-injected fields (`user_role`, `position`) live inside the JWT payload only. Use `extractClaimsFromAccessToken(session.access_token)` when claims include hook-added fields; `extractClaims(user.app_metadata)` still works but only returns DB-mirrored fields (`tenant_id`, `branch_id`, `role`). Caught by: `position` claim missing from UI on 2026-04-22 despite hook emitting it correctly.
- [2026-04-22] RLS-PERMISSIVE-POLICIES-OR — PostgreSQL RLS combines multiple PERMISSIVE policies on the same command with **OR**. Two permissive SELECT policies `(user_id = auth.uid())` and `(tenant_id = X)` together let anyone in the tenant see every row, not just their own. Either collapse to a single policy with the combined predicate, or mark one policy `AS RESTRICTIVE`. When writing self-scope + admin-scope policies, always gate the admin policy behind a permission check (e.g. `has_permission(NULL, 'staff:assign_permission')`). Caught by: cashier seeing 192 tenant-wide + 61 branch grants at `/employee/permissions` on 2026-04-22.
- [2026-04-02] CONSTRAINT-BEFORE-CLEANUP — Never add CHECK constraints before cleaning up existing data that would violate them. ALTER TABLE ADD CONSTRAINT will fail on dirty data and block all subsequent statements in the migration.
- [2026-04-02] REVOKE-ALL-DML — When locking down a table to RPC-only, revoke INSERT + UPDATE + DELETE (not just UPDATE). Leftover INSERT/DELETE grants create bypass paths that orphan related rows (e.g. auth.users without profiles breaks JWT hook).
- [2026-04-02] ROLE-SCOPE-CONSISTENCY — When a role is defined as "HQ-wide" or "tenant-wide" in one place, ensure ALL references (RLS policies, docs, spec tables) agree. office was HQ-wide in role table but branch-scoped in SELECT policy.
- [2026-04-02] TYPE-STUB-BEFORE-CODE — When adding a new DB table, check `database.types.ts` first. If the table isn't in the generated types, add a type stub BEFORE writing any code that calls `.from("new_table")`. Otherwise typecheck passes locally but build fails.
- [2026-04-02] VERIFY-BEFORE-DONE — Never mark a task completed until `pnpm typecheck && pnpm lint && pnpm build` output is confirmed green. Generated types may have `| null` where manual stubs assumed non-null.
- [2026-04-02] LINT-BEFORE-COMMIT — Always run `pnpm lint` before committing. CI runs typecheck + lint + build; skipping lint locally causes CI failures on push. `/verify` must include all three.
- [2026-04-09] NO-ARBITRARY-DIMENSIONS — Never use arbitrary dimension values like `text-[10px]`, `w-[200px]`, `h-[3rem]` in Tailwind classes. ESLint rule `design-system/no-arbitrary-tailwind-value` enforces this at error level. Use standard Tailwind tokens or extend `@theme` in globals.css. For viewport-based values, add custom utilities instead.
- [2026-04-14] NO-SURFACE-THEME-IMPORTS — Never import per-domain `theme.css` files to restyle a surface. Route all surface differentiation through shared tokens, utilities, and recipe variants instead.
- [2026-04-14] NO-STATIC-UI-INLINE-STYLES — Never add static `style={{ ... }}` blocks to foundation, shell, auth, or mobile chrome files. Move static presentation into `globals.css`, shared utilities, or recipe helpers. Inline style is allowed only for truly dynamic runtime values.
- [2026-04-14] BLOCKED-STATE-UI-IS-PRESENTATION-ONLY — Shared blocked-state helpers may parse `forbidden` / `reason` and render copy, but they must never become a second auth policy layer or change redirect targets.
- [2026-04-15] TERMINOLOGY-SOURCE-OF-TRUTH — Never introduce new domain/UI wording by ad-hoc hardcoded copy when an existing canonical term already exists. Business meaning and naming rules live in `docs/ref/glossary.md`; shared Vietnamese labels live in `packages/shared/src/labels/vi.ts`; inventory-specific route/term adapters live in `apps/web/app/inventory/_lib/dictionary.ts`. When adding or changing copy, update one of those sources first or in the same PR, run `pnpm lint:copy`, and avoid reintroducing drift terms like `Employee Portal`, `Admin Shell`, `Báo cáo CEO`, `Bếp dùng`, `Kiểm kê kho`, `Danh sách phiếu xuất`, `Chủ hệ thống`, `Quản lý cấp cao`, `Trụ sở chính`, or `Ngừng`.
- [2026-04-16] PRESET-FIRST-UI — Never add UI rules, wrappers, docs, or utilities that outrun the current shadcn preset. The project preset is defined by `packages/ui/components.json`, `apps/web/components.json`, `apps/web/app/globals.css`, and `apps/web/app/layout.tsx`.
- [2026-04-16] NO-PRIMITIVE-DESIGN-OVERRIDE — Never redefine the visual contract of core primitives like `button`, `table`, `sidebar`, `card`, or `badge` through page-level wrappers or docs. Reuse the current preset-backed primitives instead of creating a parallel design system.
- [2026-04-16] DOCS-MUST-MATCH-RUNTIME — UI docs must describe the actual runtime configuration. When changing `components.json`, `globals.css`, or `layout.tsx`, update `docs/spec/design-system.md` and `docs/modules/ui.md` in the same change so docs do not drift from the live preset.
- [2026-04-16] NO-LEGACY-APP-HELPERS — Do not keep or introduce legacy helper classes such as `app-*`, `safe-top`, or `safe-bottom` in runtime UI. Replace them with direct shadcn primitive composition and standard utility classes.
- [2026-04-16] NO-FAKE-PRIMITIVES — Never use raw `div` / `span` / `p` markup to imitate preset primitives such as `Card`, `Badge`, `Button`, `Table`, `Tabs`, `Input`, or `Select`. If the UI reads like an existing primitive, use that primitive directly instead of hand-styling a clone.
