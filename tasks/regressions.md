# Regressions — Named Failure Rules

> Loaded at the start of every session. Each line prevents a past mistake from recurring.
> Format: [DATE] [RULE NAME] — short description

- [2026-04-23] INVENTORY-BRANCH-FILTER-URL-ONLY — Inventory scope ALWAYS flows through URL `?branchId=` (see `apps/web/app/inventory/_lib/inventory-scope.ts#resolveInventoryBranchScope`). Never persist selection to localStorage, cookies, or React context. Server Actions that mutate branch-scoped data MUST take an explicit `branchId` input and re-validate it against the resolver's `allowedBranches` — never trust URL params as a write target. Multi-item RPCs (GRN confirm, transfer commit, stocktake post, production yield) MUST receive a concrete `branchId`; never pass "all" or null. Reports and dashboard aggregation are the ONLY pages allowed to ignore the param.
- [2026-04-23] PO-STATUS-DERIVATION-IN-RPC — Purchase-order status derivation (`sent` → `partially_received` / `received`) triggered by GRN confirmation MUST live inside `confirm_goods_receipt_note` RPC, locked via `SELECT … FROM purchase_orders … FOR UPDATE`. Never re-introduce app-layer computation (pre-fetch `po_id` + read siblings + `UPDATE purchase_orders`): two concurrent confirms against the same PO race and can clobber each other's status. Tolerance is ±5% per ingredient (lower bound only) per `docs/ref/inventory.md §7`. The RPC now returns `{grn_id, status, journal_entry_id, po_id, po_status}` — callers read `po_id` from the response for revalidatePath.
- [2026-04-22] DESIGN-SYSTEM-CONTRACT-FIRST — Before any UI/UX rebuild, read `docs/spec/design-system.md` and `docs/modules/ui.md`, then state the surface, primary user job, route family, change type, and shadcn primitives used. Never start from a new theme, fake primitive, route-specific visual system, or vocabulary source.
- [2026-04-23] PLPGSQL-RECORD-IS-NOT-NULL — `IF record IS NOT NULL` in PL/pgSQL returns TRUE **only when every column is non-null**, not when a row was found. Tenant-level users with `branch_id IS NULL` silently fell out of the JWT hook because one nullable column tripped the check. Check a guaranteed-non-null column (`record.tenant_id IS NOT NULL`) or use `FOUND` after the SELECT. Caught by: area_manager / office / super_manager login returning empty `app_metadata` on 2026-04-23.
- [2026-04-22] JWT-CLAIMS-NOT-IN-APP-METADATA — `session.user.app_metadata` (supabase-js) reads from the `auth.users` row, NOT from JWT claims. Hook-injected fields (`user_role`, `position`) live inside the JWT payload only. Use `extractClaimsFromAccessToken(session.access_token)` when claims include hook-added fields; `extractClaims(user.app_metadata)` still works but only returns DB-mirrored fields (`tenant_id`, `branch_id`, `role`). Caught by: `position` claim missing from UI on 2026-04-22 despite hook emitting it correctly.
- [2026-04-22] RLS-PERMISSIVE-POLICIES-OR — PostgreSQL RLS combines multiple PERMISSIVE policies on the same command with **OR**. Two permissive SELECT policies `(user_id = auth.uid())` and `(tenant_id = X)` together let anyone in the tenant see every row, not just their own. Either collapse to a single policy with the combined predicate, or mark one policy `AS RESTRICTIVE`. When writing self-scope + admin-scope policies, always gate the admin policy behind a permission check (e.g. `has_permission(NULL, 'staff:assign_permission')`). Caught by: cashier seeing 192 tenant-wide + 61 branch grants at `/employee/permissions` on 2026-04-22.
- [2026-04-02] CONSTRAINT-BEFORE-CLEANUP — Never add CHECK constraints before cleaning up existing data that would violate them. ALTER TABLE ADD CONSTRAINT will fail on dirty data and block all subsequent statements in the migration.
- [2026-04-02] REVOKE-ALL-DML — When locking down a table to RPC-only, revoke INSERT + UPDATE + DELETE (not just UPDATE). Leftover INSERT/DELETE grants create bypass paths that orphan related rows (e.g. auth.users without profiles breaks JWT hook).
- [2026-04-02] ROLE-SCOPE-CONSISTENCY — When a role is defined as "HQ-wide" or "tenant-wide" in one place, ensure ALL references (RLS policies, docs, spec tables) agree. office was HQ-wide in role table but branch-scoped in SELECT policy.
- [2026-04-02] TYPE-STUB-BEFORE-CODE — When adding a new DB table, check `database.types.ts` first. If the table isn't in the generated types, add a type stub BEFORE writing any code that calls `.from("new_table")`. Otherwise typecheck passes locally but build fails.
- [2026-04-02] VERIFY-BEFORE-DONE — Never mark a task completed until `pnpm typecheck && pnpm lint && pnpm build` output is confirmed green. Generated types may have `| null` where manual stubs assumed non-null.
- [2026-04-02] LINT-BEFORE-COMMIT — Always run `pnpm lint` before committing. CI runs typecheck + lint + build; skipping lint locally causes CI failures on push. `/verify` must include all three.
- [2026-04-09] NO-ARBITRARY-DIMENSIONS — Never use arbitrary dimension values like `text-[10px]`, `w-[200px]`, `h-[3rem]` in Tailwind classes. ESLint rule `design-system/no-arbitrary-tailwind-value` enforces this at error level. Use standard Tailwind tokens or extend `@theme` in globals.css. For viewport-based values, add custom utilities instead.
- [2026-04-14] NO-SURFACE-THEME-IMPORTS — Never import per-domain `theme.css` files to restyle a surface. Route all surface differentiation through shared tokens, utilities, and recipe variants instead.
- [2026-04-14] NO-STATIC-UI-INLINE-STYLES — Never add static `style={{ ... }}` blocks to foundation, shell, auth, or mobile chrome files. Move static presentation into `globals.css`, shared utilities, or recipe helpers. Inline style is allowed only for truly dynamic runtime values.
- [2026-04-14] BLOCKED-STATE-UI-IS-PRESENTATION-ONLY — Shared blocked-state helpers may parse `forbidden` / `reason` and render copy, but they must never become a second auth policy layer or change redirect targets.
- [2026-04-15] TERMINOLOGY-SOURCE-OF-TRUTH — Never introduce new domain/UI wording by ad-hoc hardcoded copy when an existing canonical term already exists. Business meaning and naming rules live in `docs/ref/glossary.md`; shared Vietnamese labels live in `packages/shared/src/labels/vi.ts`; inventory-specific route/term adapters live in `apps/web/app/inventory/_lib/dictionary.ts`. When adding or changing copy, update one of those sources first or in the same PR, run `pnpm lint:copy`, and avoid reintroducing drift terms like `Employee Portal`, `Admin Shell`, `Báo cáo CEO`, `Bếp dùng`, `Kiểm kê kho`, `Danh sách phiếu xuất`, `Chủ hệ thống`, `Quản lý cấp cao`, `Trụ sở chính`, or `Ngừng`.
- [2026-04-16] PRESET-FIRST-UI — Never add UI rules, wrappers, docs, or utilities that outrun the current shadcn preset. The project preset is defined by `packages/ui/components.json`, `apps/web/components.json`, `apps/web/app/globals.css`, and `apps/web/app/layout.tsx`.
- [2026-04-16] NO-PRIMITIVE-DESIGN-OVERRIDE — Never redefine the visual contract of core primitives like `button`, `table`, `sidebar`, `card`, or `badge` through page-level wrappers or docs. Reuse the current preset-backed primitives instead of creating a parallel design system.
- [2026-04-16] DOCS-MUST-MATCH-RUNTIME — UI docs must describe the actual runtime configuration. When changing `components.json`, `globals.css`, or `layout.tsx`, update `docs/spec/design-system.md` and `docs/modules/ui.md` in the same change so docs do not drift from the live preset.
- [2026-04-16] NO-LEGACY-APP-HELPERS — Do not keep or introduce legacy helper classes such as `app-*`, `safe-top`, or `safe-bottom` in runtime UI. Replace them with direct shadcn primitive composition and standard utility classes.
- [2026-04-16] NO-FAKE-PRIMITIVES — Never use raw `div` / `span` / `p` markup to imitate preset primitives such as `Card`, `Badge`, `Button`, `Table`, `Tabs`, `Input`, or `Select`. If the UI reads like an existing primitive, use that primitive directly instead of hand-styling a clone.
- [2026-04-24] RLS-NOT-APPLIED-ON-MV — Postgres RLS on the base table is NOT inherited by materialized views. Dashboard MVs like `mv_inventory_stock_current`, `mv_grn_price_baseline`, and `mv_inventory_value_ranking` bypass tenant/branch RLS if queried directly by role `authenticated`. Always `REVOKE ALL ... FROM authenticated` on the MV and expose access only through a `SECURITY DEFINER` function that re-checks `tenant_id`, `branch_id`, and `has_permission(branch, key)` in SQL. Caught during inventory redesign workshop 2026-04-24 before any leak. Reference: `docs/plan/inventory-redesign.md §Q5`.
- [2026-04-24] SHIFT-KEY-CANONICAL — "Ca làm việc" in inventory / GRN express / waste anti-splitting uses the canonical string `YYYY-MM-DD_{morning|afternoon|evening}` computed against `branches.timezone` with business-day cutoff 04:00 local. Never use `pos_sessions.id`, raw `created_at`, or `date_trunc('day', now())` — those drift with timezone and don't handle overnight shifts. Helper `inventory_shift_key(branch_id, at timestamptz)` is the single source of truth. Reference: `docs/plan/inventory-redesign.md §Q1 + §B2`.
- [2026-04-24] BASELINE-SAMPLE-MIN — GRN price variance baseline (`avg_30d_same_supplier_same_item`) MUST check `sample_n >= 3` before applying any tier rule. With fewer samples, the baseline = the only GRN itself → variance always 0 → every price "passes" including gaming the first GRN of a new supplier. Fallback order: `avg_30d_any_supplier_same_item` (n≥3) → QLV manual approval required. After a hard-block override, set `baseline_paused=true` for 30 days on `(supplier, ingredient)` to prevent outlier pricing from poisoning the average. Reference: `docs/plan/inventory-redesign.md §Q3`.
- [2026-04-24] PERIOD-CLOSE-SOFT-HARD — Inventory mutations (waste, adjustment, stocktake finalize) respect `accounting_periods` two-stage close: soft-close day 5 of next month (back-dated posts auto-shift to current period with `originally_dated_in_prior_period=true` flag); hard-close day 15 (reject any back-dated write, `period_reopen` permission + 2FA required to override). Never silently post to a closed period — trigger `enforce_period_close()` on all write paths. Never add `ON CONFLICT DO NOTHING` to bypass the trigger. Reference: `docs/plan/inventory-redesign.md §B8`.
- [2026-04-24] OFFLINE-NO-SILENT-CLIENTWINS — Offline stocktake sync conflicts MUST be materialized as `stocktake_conflicts` rows and resolved by QLV through the queue UI. Never auto-merge with "client-wins" or "last-write-wins" silently — stocktake adjustments drive accounting and shrink detection, and silent overwrite of a legitimate count destroys audit trail. Server validates `offline_created_at` within `[session_opened_at, now()]` window to block clock tamper. Reference: `docs/plan/inventory-redesign.md §Q7`.
- [2026-04-24] STOCKTAKE-BLIND-STRIP-SERVER-SIDE — Blind-mode counter UI MUST fetch lines through `get_stocktake_lines_blind` (SECURITY DEFINER) — never through `.from("stocktake_lines").select(...)`. The RPC strips `system_quantity` server-side before the payload crosses the RLS boundary. Client code must not re-query the base table or reference a `system_quantity` field — if the network payload contains that key, blind mode is broken and the whole monthly/quarterly/spot integrity chain collapses. Reference: S13a Day 4 count page `apps/web/app/inventory/stocktake/[id]/count/page.tsx`.
- [2026-04-24] DRAFT-AUTOSAVE-CASCADE — Stocktake draft auto-save (`stocktake_drafts`) must CASCADE-delete when the parent `stocktake_sessions` row is removed (migration `20260425180000_s13a_stocktake_drafts.sql` uses `ON DELETE CASCADE`). Never replace with `ON DELETE SET NULL` or a manual trigger — stale drafts attach to session ids that get reused by identity sequence reset, silently feeding old counts into a new session. Debounce stays at 30 s client-side (spec §Q2); re-saves skip when serialized counts match previous save to avoid write amplification.
- [2026-04-24] ZONE-LOCK-HEARTBEAT-THIRD-TTL — `heartbeat_zone_lock` must fire at ≤ 1/3 of the TTL window, not at the TTL itself. Default TTL 1800 s → heartbeat every 600 s. Firing at or near TTL means any single network hiccup drops the lock. `ZoneLockIndicator` implements this; `onLost` callback flips the page into read-only mode — never silently retry as the holder after losing ownership.
- [2026-04-24] PAYMENT-AUTO-COMPLETES-ORDER — POS payment confirm RPCs (`confirm_payment_and_post`, `complete_payment_and_consume_stock`, `create_payment` cash branch) MUST call `finalize_paid_order(order_id, actor_id)` after `payment_status='paid'` so `orders.status='completed'` and trigger `trg_release_table_on_order_status` releases the table. Semantic: `orders.status='completed'` means "paid + closed from POS view" — NOT "kitchen done". Helper MUST NOT force `order_items.status` or `kds_tickets.status` — chef keeps cooking via KDS after payment so pay-first-cook-after (takeaway rush, customer in a hurry) still works. Bill sheet UI MUST call `onClose()` after confirm success; never re-enable the old "Hoàn tất và trả bàn" button that required `status='served'` — completion is automatic now. When adding new payment RPCs, always `PERFORM public.finalize_paid_order(order_id, actor_id)` as the last step. Reference: `supabase/migrations/20260426030000_auto_complete_paid_order.sql`.
- [2026-04-24] R4-ESCALATE-NOTE-MIN-CHARS — `escalate_round_4` RPC enforces `length(note) >= 20` server-side (raises `22023`). UI MUST mirror that check in both the Zod schema (`z.string().min(20, ...)`) AND the form submit guard before the action call so the counter never gets a stale 500. Drop to 10 chars or skip the note → next audit cannot reconstruct why QLV+Admin overrode R3 counts. When changing the threshold, update the RPC, the Zod schema, AND the `(N/20)` char counter label together. Reference: `escalate-client.tsx` + `supabase/migrations/20260425120000_s5_stocktake_blind_recount_abc.sql`.
- [2026-04-24] CONFLICT-RESOLVE-VIA-RPC-ONLY — Stocktake conflict resolution MUST go through `resolve_stocktake_conflict` RPC. Never direct-update `stocktake_lines.counted_quantity` from the queue UI to "apply client" — bypasses the conflict ledger update (`resolved_at`, `resolution`, `resolution_qty`, `resolution_note`), breaks audit trail, and lets a second QLV re-resolve the same row. The 4 resolution modes (`keep_server` / `apply_client` / `manual_value` / `reject`) are enumerated server-side; adding a 5th mode requires RPC change first, then client. `manual_value` without `p_manual_qty` raises `22023` — client must enforce before dispatch.
- [2026-04-24] FINALIZE-R1-FINAL-GATE — `finalize_stocktake` refuses to complete a session while any R1 line has `is_final=false` (raises `22023 cannot finalize: X round-1 line(s) still not final`). Never bypass by direct `UPDATE stocktake_sessions SET status='completed'` — R4 escalation is the ONLY legitimate path from R3 → R1 final. The escalate RPC writes a round-4 line AND sets the round-1 line's `is_final=true` with the escalated qty, so after all escalations the gate passes automatically. UI finalize button MUST be disabled while `needEscalation.length > 0`.
- [2026-04-24] AUTO-WASTE-NON-FATAL — POS void + KDS cancel auto-generated waste (`create_waste_from_order` RPC + `createWasteFromOrder` action) MUST NOT fail the parent void/cancel operation. The action always returns `{ success: true }`; failures surface via `data.softFailed=true` with `data.softError` message so the host shows a warning toast ("admin sẽ xử lý") while the underlying void/cancel completes. Never rewrite the action to raise / return `{ success: false }` — a cashier confirming payment void cannot be blocked because photo-EXIF validation or permission gate rejected the waste row. Pair with `showAutoWasteToast` for uniform messaging. Reference: `apps/web/app/inventory/waste-actions.ts#createWasteFromOrder`.
- [2026-04-24] KDS-CANCEL-STAGE-STEP-5 — `KdsCancelStagePicker` ratio slider for `mid_cook` uses **step=5**, not 1. Finer steps (1%) let a malicious chef split 30% into 6×5% fragments each under the anti-split rolling-sum threshold. Step=5 makes "split-into-smaller" still register as one event in the 15-minute rolling window. When adding new stage types (e.g. `parbaked`, `par_cooked`) keep the same step. Before `after_cook` is the 100% waste; `before_cook` emits `wasteSourceType=null` so the host short-circuits the RPC entirely (no phantom 0-qty rows).
- [2026-04-24] TRUST-SELF-VIEW-NO-GATE — Self-view of `user_trust_score` (`getMyTrustScore` in `apps/web/app/inventory/trust-actions.ts`) MUST use `getAuthContext([])` — no permission gate. Users always see their own score. Gating with `REPORTS_VIEW_BRANCH` (as the admin leaderboard does) hides the score from the very cashiers/chefs whose GRN activity drives it, defeating the transparency goal of §Q4b. The admin LEADERBOARD keeps the `reports:view_branch` gate to avoid peer ranking leakage. When adding trust-related actions, default to gate ONLY the cross-user view; always allow self.
- [2026-04-24] TRUST-COMPUTE-OPT-IN — `getTrustLeaderboard(branchId, { includeComputed: true })` fires up to 25 RPC calls to `compute_user_trust_score`. Default `includeComputed=false` — live compute MUST be opt-in per request via `?computed=1` URL param so dashboards don't hammer the RPC. Self-view (`getMyTrustScore`) calls RPC unconditionally since it's a single invocation. When bumping the 25-row cap, weigh RPC cost × 10 000 staff-branches; cap exists to keep RSC render under 2 s.
- [2026-04-24] GET-AUTH-CONTEXT-EMPTY-ARRAY-REJECTS — `getAuthContext([])` in `apps/web/app/_lib/auth.ts` rejects **every** authenticated user because `allowedRoles.includes(claims.user_role)` is false on an empty array. When an action only needs "authenticated, any role" (e.g. self-view trust score, read-only feature-flag matrix), pass `STAFF_ROLES` from `@comtammatu/shared/auth` — NOT `[]`. Symptom: correct-looking perm check but always returns `{ success: false, error: "Chưa đăng nhập" }` even for owners. Caught by: owner hitting `/admin/inventory/feature-flags` and seeing "Chưa đăng nhập" despite valid session on 2026-04-24.
- [2026-04-24] MCP-APPLY-VS-CLI-PUSH — Prefer `supabase db push` from CI for production deploys; reserve MCP `apply_migration` for dev exploration only. MCP auto-generates migration version from wall-clock `applied_at`, while local filename timestamps drive `supabase db push`. Mixing the two on the SAME database causes `schema_migrations` drift: local filename `20260425050000_s0a` can appear on dev as version `20260423172706_s0a`. Drift is cosmetic on prod (empty → push writes filename timestamps cleanly) but breaks `supabase db pull` and `db reset` on dev. Caught during Inventory Redesign post-ship audit 2026-04-24 — 15 migrations drifted on dev DB `iexwsuaqqenyjiskawoj`. Reference: `docs/plan/inventory-redesign.md` post-S9 review.
