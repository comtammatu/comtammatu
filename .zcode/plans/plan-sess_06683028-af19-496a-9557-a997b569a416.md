### Phần 1 — Migration tái tạo policy receive (DB-first, file only, owner apply)
Tạo `supabase/migrations/20260729160000_restore_branch_ops_realtime_policy.sql`:

```sql
-- Policy branch_ops_receive trên realtime.messages bị mất khỏi active chain khi
-- baseline 20260727120000 được dựng lại (pg_dump --schema=public,private loại
-- schema realtime). Server vẫn realtime.send(...) lên topic 'branch:{id}:ops'
-- (baseline.sql:7282,7331) nhưng không client nào được policy cho nhận → storm
-- Unauthorized. Tái tạo policy duy nhất nhận trên topic này, hẹp vào predicate
-- can_read_branch_ops(bigint) đã có sẵn (baseline.sql:7804, grant :63841).

DROP POLICY IF EXISTS "branch_ops_receive" ON realtime.messages;

CREATE POLICY "branch_ops_receive"
ON realtime.messages
FOR SELECT TO authenticated
USING (
  realtime.topic() ~ '^branch:[1-9][0-9]*:ops$'
  AND public.can_read_branch_ops(
    split_part(realtime.topic(), ':', 2)::bigint
  )
);
```

Lý do khác codex đề xuất (đã hiệu chỉnh):
- **BỎ filter `realtime.messages.extension = 'broadcast'`** — đó là hallucination (Explore agent xác nhận codebase không bao giờ reference cột này; migration introspect `realtime.messages` chỉ check `topic`/`private`). Nếu cột không tồn tại → policy ném error khi evaluate.
- **Giữ regex `^branch:[1-9][0-9]*:ops$`** thay `LIKE 'branch:%:ops'` của archive gốc — tránh `split_part` cast lỗi khi topic malformed (vd `branch::ops` segment rỗng). Regex match trước thì mới vào nhánh cast → an toàn.
- **BỎ `CASE WHEN ... ELSE FALSE`** không cần — regex không match → AND short-circuit false, gọn hơn.
- **Không `ALTER TABLE ENABLE RLS`** — Supabase quản lý RLS cho `realtime.messages` sẵn.

Migration là file-only. Theo rule database.md: production áp dụng file→PR→owner apply; Greenfield/Preview cần owner delegation. **Tôi không tự apply.**

### Phần 2 — Dập rejoin loop client (generic ở `use-realtime-channel.ts`)
Sửa `apps/web/app/_hooks/use-realtime-channel.ts` (single point cho mọi creator, benefit tất cả private channel: branch ops, notifications, kds, pos-order...):

Wrap `setupRef.current(...)` kết quả channel: hook `.subscribe` callback của **channel đã tạo** để:
- Khi `status === "CHANNEL_ERROR"` và `err.message`/`err.cause` match `/unauthorized|permission|denied/i` → đây là terminal authorization reject → **gọi `teardownChannel()` ngay** (đã có sẵn `evict`/`removeChannel` → reset `rejoinTimer` + state closed ở Phoenix `channel.js:112-119,239`). Đánh dấu `terminalError = true` để `subscribeWithToken`/auth-event không subscribe lại.
- Giữ retry cho `TIMED_OUT` / transport error (non-terminal).

Cách tiếp cận: vì `setupChannel` của caller đã `.subscribe()` sẵn và trả `RealtimeChannel`, ta không thể bọc callback của họ. Thay vào đó thêm 1 **`.on('system', ...)`** listener? — KHÔNG, không có system event cho JOIN error. 

**Cách chính xác**: thay đổi signature contract — `setupChannel` trả về channel, nhưng ta cần bắt callback subscribe. Vì 2 caller đã tự `.subscribe(...)`, ta thêm listener **sau khi** nhận channel bằng `channel.subscribe(...)` lần nữa? — KHÔNG, double-subscribe sai.

**Solution chọn**: Hook vào error qua **channel state polling** là xấu. Thay vào đó, sửa ở 2 caller (`use-branch-ops-events.ts:28-36` và `use-pos-menu-sync.ts:72-80`) — thêm nhánh `CHANNEL_ERROR` trong callback `.subscribe` của họ, gọi `removeChannel` (truyền `supabase` vào hoặc trả channel lên hook để hook teardown).

Cụ thể cho từng creator, đổi callback:
```ts
.subscribe((status, err) => {
  if (status === "CHANNEL_ERROR") {
    const text = `${err?.message ?? ""} ${err?.cause ? JSON.stringify(err.cause) : ""}`;
    if (/unauthorized|permission|denied/i.test(text)) {
      // Terminal: RLS/server reject. Stop Phoenix rejoin loop.
      supabase.removeChannel(channel);  // channel = return value đang build
      return;
    }
    // Non-terminal transport error: let Phoenix retry.
    return;
  }
  if (status === "SUBSCRIBED") { /* existing logic */ }
});
```
Vấn đề: trong pattern `.channel(...).on(...).subscribe(cb)` channel chưa gán vào biến khi cb chạy. Refactor: gán `const channel = supabase.channel(...)` rồi `channel.on(...).subscribe(cb)`, trong cb tham chiếu `channel` (closure). Hai file đều cần refactor nhỏ này.

**Decision scope**: sửa ở 2 creator cụ thể (branch ops) thay vì generic `use-realtime-channel.ts`, vì:
- Rejoin-loop-on-Unauthorized chỉ là vấn đề cho private topic bị RLS reject (branch ops + future private). Public topic không bị.
- Tránh thay đổi contract generic hook ảnh hưởng 5+ caller khác.
- Codex cũng recommend "ở cả hai creator".

(Nếu sau này có thêm private topic, pattern này tái dùng được.)
