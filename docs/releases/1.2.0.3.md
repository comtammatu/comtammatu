# Release `1.2.0.3` — Repo metadata: CODEOWNERS + PR / issue templates (2026-05-09)

> **Patch on top of `1.2.0.2`.** Four GitHub-convention files added to `.github/`. No source change, no behavior change for end users, no Vercel deploy required for these to take effect (GitHub serves them directly). Tag: `1.2.0.3`.

## What changed

| File                                        | Purpose                                                                                                                                                           |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.github/CODEOWNERS`                        | Routes review/approval requests for every path to `@comtammatu`. Single-tenant CTCP fallback rule today; path-specific overrides go above it when the team grows. |
| `.github/pull_request_template.md`          | Default PR body. Mirrors the CLAUDE.md quality gates so a contributor sees the checklist before the reviewer asks.                                                |
| `.github/ISSUE_TEMPLATE/bug_report.md`      | Bug intake form. Repro / expected / actual / environment / severity. Auto-labels `bug` and assigns `@comtammatu`.                                                 |
| `.github/ISSUE_TEMPLATE/feature_request.md` | Proposal intake form. Problem / proposal / acceptance criteria / risk surface / explicit out-of-scope. Auto-labels `enhancement`.                                 |

## Why now

After 5 Ralph cycles + 21 commits + 2 prior releases (`1.2.0.1` security/reliability hardening, `1.2.0.2` robots.txt + security.txt), the load-bearing engineering work is shipped. Repo metadata is the next-layer hygiene that makes future contribution + triage cheaper:

- **CODEOWNERS** becomes load-bearing once a second contributor joins. Today it just makes the auto-request explicit.
- **PR template** front-loads the CLAUDE.md gates (typecheck/lint/build/tests + regression-rule discipline + no `Co-Authored-By: Claude`) so reviewers don't have to re-paste the checklist on every PR.
- **Issue templates** turn a free-form "this doesn't work" into structured triage data: severity, branch scope, commit SHA, screenshots-or-it-didn't-happen evidence.

## Why a patch (not a minor)

Zero behavior change. Zero source change. The diff touches only `.github/`, `VERSION`, `CHANGELOG.md`, and the release-notes file. Same versioning convention as the prior two releases (`1.2.0.0` was the QR feedback module headline minor; `1.2.0.1` and `1.2.0.2` were patches; `1.2.0.3` is also a patch).

## Known limitations

- **CODEOWNERS does NOT enforce review on its own.** It only auto-requests review. Branch protection rules ("Require review from Code Owners") need to be configured in GitHub repo settings to enforce — that's owner-managed and out of scope for this commit.
- **Issue templates use front-matter `assignees:`.** GitHub honors this if `comtammatu` has access to the repo (which they do — they own it). If a future repo move splits the GitHub user from the project owner, both templates need an update.
- **PR template `[ ]` checkboxes.** GitHub renders these clickable in the web UI but does NOT enforce them. The reviewer is the gate, not the checkbox state.
