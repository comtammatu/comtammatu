## Known limitations

- **Dependabot can flood the PR queue.** The first scan after enabling will likely batch a large number of pending updates. The `open-pull-requests-limit: 5` cap and the `production-dependencies` / `dev-dependencies` groups should keep this manageable, but the owner should expect to triage 2-5 grouped PRs in the first month.
- **Major-version bumps are explicitly ignored** in dependabot.yml (`version-update:semver-major` for all packages). These need deliberate upgrade PRs (e.g. Next.js 16 → 17 when it lands), not Dependabot. This is an intentional safety choice, not a bug.
- **SECURITY.md does NOT enforce reviewer triage.** It only surfaces the policy on the GitHub Security tab. The owner is still the gate; the document is informational for reporters.
- **The 5-business-day acknowledgement SLO is best-effort** — single-tenant CTCP, single owner. If you're a researcher and you don't hear back, ping the email again or open a low-detail "ping" GitHub issue (don't include vulnerability details there).
- **Dependabot ICT timezone** assumes the owner is on `Asia/Ho_Chi_Minh`. If the project moves regions, update `dependabot.yml` accordingly.
