## Why now

Cycle 7 shipped `.github/SECURITY.md` (vulnerability-reporting policy) and `.github/dependabot.yml` (dependency hygiene). The next adjacent layer is **automated SAST** — CodeQL is GitHub's native answer and integrates with the Security tab that SECURITY.md now populates. Without CodeQL, the security tab is a policy doc with no live findings to triage; with it, the same tab becomes the daily security dashboard.

CONTRIBUTING.md is the documentation cousin: now that the repo has CODEOWNERS (cycle 6), PR/issue templates (cycle 6), SECURITY.md (cycle 7), and Dependabot (cycle 7), a contributor needs a single entry document that references all of them and the underlying CLAUDE.md gates. Without it, every new contributor has to reverse-engineer the workflow from the file tree.

## Why a patch (not a minor)

Zero behavior change for end users. Zero source change. The diff touches only `.github/`, `VERSION`, `CHANGELOG.md`, and the release-notes file. CodeQL adds a new CI job but doesn't modify the existing `ci.yml` pipeline — so existing CI semantics are preserved. Same versioning convention as the prior four releases.

## Owner action required

**None for this release.** The push that lands `1.2.0.5` automatically triggers the first CodeQL run (because the workflow listens on `push: branches: [main]`). Expect:

- First CodeQL run completes in ~5-15 minutes (cold cache).
- Findings (if any) populate `github.com/comtammatu/comtammatu/security/code-scanning`.
- Subsequent runs use the CodeQL DB cache and finish faster (~3-8 minutes).
- The weekly cron run fires Mondays at 03:00 UTC (= 10:00 ICT). Dependabot's monthly scan fires Mondays at 08:00 ICT (= 01:00 UTC) — different cadences, no conflict, both run in low-traffic Asia morning hours.

The carry-over `1.2.0.1` + `1.2.0.2` alias-promotion blocker is unchanged — `app.comtammatu.com` is still pinned to a pre-fix Vercel build.

## Known limitations

- **CodeQL false-positive surface:** The `security-extended` suite is broader than the default; expect a handful of false positives on the first scan (esp. ReDoS heuristics on Zod regex schemas). Triage via the Security tab; dismissed-with-reason findings don't block CI.
- **Autobuild on a pnpm monorepo can mis-detect the workspace root.** If the first scan fails on a build step, replace the `Autobuild` step with explicit `pnpm install --frozen-lockfile` + `pnpm build` (or set `build-mode: none` for TS-only analysis). This is documented as a known CodeQL pattern, not a bug in our setup.
- **Pinned SHA can drift behind upstream security fixes.** Dependabot's `github-actions` ecosystem (configured in cycle 7) catches this monthly. If a critical CodeQL CVE drops mid-cycle, the owner can manually bump the SHA.
- **`security-events: write` permission is workflow-scoped** — it's NOT global on the repo, so a malicious dependency in a PR can't exfiltrate findings. The cycle 7 SECURITY.md describes the broader threat model.
- **Weekly cron timezone:** the cron runs in UTC. The 03:00 UTC pick is deliberate (10:00 ICT, post-Dependabot scan, before standard CTCP business hours).
