## Executive Verdict

The system is **healthy and well-disciplined at its load-bearing layers**, with the real debt concentrated in scale-ahead performance and platform under-utilization rather than correctness. The package boundaries are genuinely clean (zero data-gateway leaks into client components, acyclic graph), the auth model is a true single gate (`apps/web/proxy.ts` decoding signed JWT claims, RLS as the authoritative data gate via `has_permission`), the RPC surface is hardened (0 mutable-search_path definers, 0 anon-callable privileged RPCs, identity-bound writers), and webhook/payment idempotency is exemplary. **There are no P0s.** The dominant problems are cross-cutting: (1) dozens of unbounded list fetches over-fetch full tables on every page load; (2) the DB is over-indexed (171 unused indexes) not under-indexed; (3) Vercel platform features that matter for a tablet-POS app are entirely absent (`maxDuration`, Speed Insights, streaming Suspense, `'use cache'`); (4) Supabase advisors (528 outstanding lints) never gate CI, so hardening is perpetual manual archaeology; (5) two privilege-escalation latent gaps (self-grant, direct PostgREST RPC perimeter) that are safe today but load-bearing on convention; (6) over-broad realtime fanout on hot tables; and (7) convention fragmentation inside `apps/web`.

## Top Themes

1. **Unbounded list fetches are the single most repeated defect.** At least 12 server actions return full result sets with eager joins and no `LIMIT`/pagination, run on every page load — `fetchPurchaseOrders`, `fetchGrns`, `fetchSupplierInvoices`, `fetchStockIssues`, `fetchSupplierReturns`, `fetchStockTransfers`, `fetchStocktakeSessions`, `fetchIngredients` (select `*`, up to 2000 rows, fetched 3× per session), plus the `hr/staff` profiles fetch and the printers/jobs 200-row hard cap. The receiving hub fetches three full payloads just to render three integer badge counts. None are broken today; all degrade linearly with operational volume.

2. **The database is over-indexed, not under-indexed.** 171 confirmed-unused indexes (verified `idx_scan=0` lifetime) cause write amplification on the hottest insert paths (`kitchen_send_batches`, `order_items`, `orders`, `print_jobs`). The 156 "unindexed FK" advisories are mostly audit/low-cardinality columns that should NOT be blanket-indexed — proven by `idx_orders_created_by` appearing in BOTH the unused list and the unindexed-FK siblings. The correct move is selective triage, not chasing advisor counts.

3. **Vercel platform features are left on the table for a perf-sensitive surface.** `maxDuration` is set nowhere (the 240s-self-budgeting reconcile cron is silently killed at the ~15s default); no Speed Insights/Analytics means zero field Web Vitals for in-store tablets; the POS page awaits all data above its Suspense boundary so nothing streams; #184 has closed the `radix-ui` `optimizePackageImports` gap; no `'use cache'`/ISR adoption for tenant-stable data.

4. **Advisors never gate CI; hardening is reactive.** 528 outstanding lints (154 security + 374 perf) accumulate with no CI gate. The dozens of `*_security_hardening` / `revoke_*_definer` / `rls_perf_*` migrations prove gaps are caught manually after the fact. New DDL can reintroduce over-grants or unindexed FKs and ship green.

5. **Authorization is correct but the perimeter is thin and convention-dependent.** Two latent escalation gaps: `grant_permission`/`apply_template_to_user` permit privilege self-grant (no `target ≠ actor` guard), and all 149 authenticated-executable SECURITY DEFINER RPCs are directly callable via PostgREST, bypassing the proxy ACL — each RPC's internal check is the entire gate. Safe today (only owners hold the delegation key; every sampled RPC self-checks) but a single future omission = escalation invisible to the test suite.

6. **Realtime is mature and leak-free but over-broad on hot tables.** All 11 subscriptions funnel through one correct hook with proper auth-before-subscribe and teardown. The defects are fanout/filter gaps: an unfiltered `notifications` popup channel, an all-branch `payments` channel that fires full `router.refresh()` in finance owner-mode, tenant-only (always-true single-tenant) notification filters, and per-order channel churn at POS.

7. **Convention fragmentation inside `apps/web`.** Shared code lives in four-to-five parallel locations (`components` vs `_components`, three `lib` roots, `_actions` shims), server-action files split `actions.ts` vs `*-actions.ts`, KDS breaks the underscore-private folder convention POS follows, `cn` is duplicated, and 24 files exceed 800 LoC (POS client component at 2113). Mechanical and low-risk but taxes every contributor.

8. **Account-takeover hardening gaps underpin the whole trust model.** Leaked-password protection and MFA are both disabled. Every SECURITY DEFINER RPC trusts `auth.uid()`/JWT claims for tenant/branch/role binding, so a single compromised staff credential inherits that account's full RPC authority — the money/HĐĐT surface is reachable from one reused breached password.

## Architecture & Project Layout

**Summary.** Turborepo + pnpm workspaces. 5 packages (acyclic, leaf-clean): `database` (the only data gateway), `shared` (auth/module-acl SSoT + payroll/tax/hddt/kds domain), `security` (Upstash ratelimit), `print-render` (shared by web preview + agent), `ui` (Má Tư DS primitives + canonical `cn`). 2 apps: `web` (Next 16 App Router, ~150K LoC) and `print-agent`. The **enforced boundaries are genuinely clean**: 275 `"use client"` files, zero `@comtammatu/database` barrel imports, zero `/supabase/server|service` leaks into client, zero client components calling `.rpc(`/`.from(` directly, acyclic package graph. The real debt is **convention fragmentation inside `apps/web`**, not boundary violations: shared code scattered across four parallel locations, two action-naming styles, a duplicated `cn`, and 24 files over 800 LoC.
