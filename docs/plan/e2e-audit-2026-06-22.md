## 3. Self-Improving Loop (trọng tâm owner yêu cầu)

**Chẩn đoán:** FIND✅ LEARN✅ FIX/VERIFY✅ (loop từng tự bắn vào chính nó —
`9d62951a` hardened guard + fixture) nhưng **ENFORCE❌** (~1.7% promotion). Doctrine
đúng ("enforced rule = 0 context; prose rule = đọc lại mỗi session; promote-then-
delete") nhưng execution lag. Máy móc đã có (`check-regression-guards.mjs`,
`regressions:retire-candidates`, review-tier floor) — thiếu là coi promotion-rate
là metric hạng nhất.

**Thiết kế (mỗi mục agent-doable, đưa thành habit cứng + CI):**

1. **Ship-guard-with-rule (habit cứng):** mọi regression rule deterministic MỚI
   phải kèm code guard trong CÙNG PR; rule nào đã có guard → xóa prose (KB co lại
   thành staging area như doctrine hứa). State trong commit/PR body.
2. **Soft-ceiling CI:** flag khi `regressions.md` vượt N rule → ép promote-or-delete.
3. **Review-tier fail-closed:** bật `REVIEW_TIER_STRICT=1` trên PR path cho diff
   T3-floor (auth/money/migration) → under-classification BLOCK, không chỉ warn.
4. **Guard parity & coverage:** pin `.mcp.json` `read_only=true` (Claude khớp Codex);
   `lint:guard-sync` assert parity .claude/.codex; nới `guard-prod-db.mjs` cover
   connector dot-names (P1 trên).
5. **Baseline replay = CI gate:** `db:baseline:local-check` self-contained → vào
   `ci.yml` (sau khi baseline fixed) → trigger/policy ref `private.*` mà không update
   baseline/bootstrap = PR block.
6. **Audit evidence packet (CX):** mỗi finding kèm code-line + prod-SELECT(hoặc lý
   do unavailable) + owner-decision link + verification command + guard-now-prevents?
7. **Promotion-rate dashboard:** `regressions:retire-candidates` chạy định kỳ + thực
   sự xóa candidate đã có guard; theo dõi % promoted như KPI loop.

**Cơ chế chạy loop (mỗi vòng = 1 workflow run):** Audit fan-out (như phiên này) →
dedup+verify đối kháng → cross-runtime pass (Codex/Antigravity) → fix theo cluster
(executor+verifier, T3 four-perspective) → **mỗi fix land kèm 1 guard/test/runbook**
→ promote KB → đo promotion-rate. Đây chính là `ralph`/`ultrawork` "boulder" hoặc
`/loop` định kỳ nếu owner muốn tự động hoá.
